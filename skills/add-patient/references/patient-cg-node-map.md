# Patient CG description → runtime-node map

This map is based on the current `godot/systems/preop_session.gd`, `godot/ui/app.gd`, encounter/preop templates, patient-bundle loader, CG pool schemas and `tools/preop_test.gd`. Natural-language descriptions are user-facing aliases only; runtime IDs below are not to be inferred or renamed. Re-check the referenced implementation when the game changes.

“Gallery category” in import requests means the **runtime patient CG pool category** in this table. Patient-owned examination/preparation/surgery CGs do not currently have a separate unlockable patient-CG Gallery entry. Do not create one unless requested and implemented by a separate system.

## Matching and escalation procedure

1. Match each supplied image to the closest natural-language row using the user's description and visible scene semantics. Keep the user's chosen label beside the row in the import inventory.
2. Confirm context-sensitive dimensions first: required vs unnecessary preparation, anesthesia state, procedure group/surgery, and whether the image depicts an action or the following acknowledgement.
3. If there are zero candidate rows, multiple materially plausible rows, or the depicted content contradicts the candidate trigger, stop **that asset's mapping** and show the user the image label plus candidates and their IDs/branch consequences. Do not copy the image, edit the bundle, or report it connected until resolved. Independent unambiguous assets may proceed if the user requested the batch and can be safely separated.
4. After resolving, test the exact trigger through the same resolver the UI uses. Check selected pool ID, patient scope, path existence, presentation type and English-mode consistency. Static presence in JSON is insufficient.
