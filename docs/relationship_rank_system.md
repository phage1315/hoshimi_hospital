# 人物关系等级系统

## 核心结构

- “认识”和“建立羁绊”是两个独立阶段。认识后仍只是普通同事，内部等级为 `0`，界面不显示 `Lv0`。
- 完成专属的“建立羁绊”事件后，关系进入 Lv1，最高 Lv5。
- `familiarity` 是隐藏的积累值；关系等级是玩家可见的阶段。
- 熟悉度达到下一等级门槛后，下一次主动接触可以选择触发升级事件。
- 每名人物共有五个羁绊事件：一段建立 Lv1 的初始事件，以及四段 Lv2–Lv5 升级事件。
- Lv4 进入亲密关系阶段。恋爱与肉体关系可以并存，也可以只出现其中一种，由人物专属剧情和选择决定，不作为互斥的统一路线。
- 每次正式升级会解锁一项人物专属帮助。具体帮助尚未设计。

关系状态建议保存在每名人物对应的关系记录中：

```json
{
  "met": false,
  "level": 0,
  "familiarity": 0,
  "route": "colleague",
  "rank_history": [],
  "unlocked_benefits": []
}
```

`met` 与等级分开。`met: true, level: 0` 表示已经认识、可以闲谈和邀请加入手术团队，但尚未形成超越一般同事的信任。未认识的人物虽然已经存在于医院名单中，但不显示关系等级，也不能触发普通关系内容。

## 熟悉度与升级

五级版使用一条逐步放缓的累计门槛：

| 等级 | 累计熟悉度门槛 |
|---:|---:|
| 建立 Lv1 | 由专属羁绊事件触发 |
| Lv2 | 10 |
| Lv3 | 25 |
| Lv4 | 45 |
| Lv5 | 70 |

这些数值作为可配置初值，后续可按实际内容量调整。玩家界面不显示熟悉度数值或进度条。

当熟悉度达到下一等级门槛时：

1. 关系进入 `rank_ready` 状态；
2. 熟悉度暂时停在当前门槛，不再继续积累；
3. 下一次人物在场时，显示“关系似乎可以进一步加深”的升级事件入口；
4. 玩家可以触发升级事件，也可以只进行普通闲谈；
5. 完成对应升级事件后等级提高一级，并重新开放熟悉度积累。

每次升级事件只能提升一级。即使开发测试直接修改了熟悉度，也不能一次跳过多级。

Lv1 的建立不使用熟悉度门槛。人物已经认识且尚未建立羁绊时，其专属 Lv1 事件可以按地点、时间和剧情条件出现。Lv1 建立前获得的熟悉度最多积累至 Lv2 门槛，但不会显示“关系可以进一步加深”；完成 Lv1 事件后才启用正常升级判定。

熟悉度来源包括微事件、重要共同工作和其他明确标记的关系内容。普通闲谈、认识事件和重复查看人物档案不增加熟悉度。

## 五个羁绊事件

每名人物拥有五个固定事件槽位：`bond_01` 与 `rank_02` 至 `rank_05`。事件逐步承担以下叙事层次，具体内容因人而异：

| 目标等级 | 主要叙事任务 |
|---:|---|
| Lv1 | 从普通同事发展为开始产生好感，正式建立人物羁绊 |
| Lv2 | 建立相互信任，愿意分享工作以外的想法与困扰 |
| Lv3 | 关系开始暧昧，逐渐触及弱点、秘密和核心矛盾 |
| Lv4 | 确认亲密关系；恋爱和肉体关系可并存，具体表现因人物而异；解锁该人物的 H 事件与手术患者 Play |
| Lv5 | 达到人物甘愿奉献的深层羁绊，并解锁其真正作为患者经历完整治疗与手术流程 |

羁绊与升级事件必须由玩家主动触发，不因完成看诊或手术而自动插入。事件完成时统一执行等级变化与帮助解锁；事件内部选择可以留下记忆标签或改变信任、好感和尊重。

Lv4 只定义亲密程度，不强制所有人物采用相同关系形式。恋爱状态仍可由 `route` 保存；肉体关系、恋爱与肉体关系并存、或人物特有的相处方式由事件记忆旗标保存。未进入恋爱路线也不会自动阻止 Lv4、Lv5，具体条件由各人物剧情决定。

## 特殊前置条件占位

人物事件的 `conditions` 现包含：

```json
"special_requirements": []
```

当前版本已经支持人物事件使用主角属性下限：

```json
{"type": "player_attribute", "attribute": "skill", "minimum": 56}
```

其中 `attribute` 可使用 `skill`、`ethics`、`charisma`、`intimidation` 或 `reputation`。未知条件类型仍会锁住事件。后续条件语法预定继续覆盖以下来源：

- 主角数值，例如技能、伦理、魅力、威慑或声望；
- 主角的身份、路线、称号或其他属性；
- 成功完成某一种术式达到指定次数；
- 成功完成某一类术式达到指定次数；
- 曾经治疗、治愈或完成某位指定患者的病例；
- 其他剧情旗标、人物事件选择或医院进度。

已实现的主角属性条件会正常判定；其他尚未实现的条件继续采用失败关闭，避免占位事件意外触发。

## 尚未确定的内容

- 特殊条件的正式数据格式及多个条件之间的 AND／OR 规则；
- 各人物每一级的帮助内容；
- 各人物在 Lv4 确认恋爱、肉体关系或两者并存的具体条件；
- 每名人物五个羁绊事件的具体故事。

## 人物在场与普通闲谈

人物能否互动，首先取决于她当前是否在该地点。地点分为两类：

- **固定活动场所**：人物在符合排班和时段时一定可以找到。飯村真奈美的固定场所是药房；非专职手术室护士的固定场所包括护士站。未来加入的影像科、手术室和妇科检查室人物，也通过各自固定活动场所配置出场。
- **随机公共场所**：职员休息室和天台从当前可出场名单中抽取人物。抽取结果需要在同一日期和时段内保持稳定，反复打开地点页面不能重新抽取。

人物在场时，根据认识状态提供不同互动：

- 尚未认识：显示初次交谈入口，完成该人物的“认识”事件；
- 已经认识但未建立羁绊：允许普通闲谈、接受手术团队邀请，并可触发 Lv1 羁绊事件；
- 已建立羁绊：显示 Lv1–Lv5，并按熟悉度开放升级；
- 达到升级条件：在普通闲谈之外，额外显示主动触发升级事件的入口；
- 有符合条件的微事件或情境事件：以独立入口或相应情境触发，不与普通闲谈混为同一行为。

普通闲谈是时间管理行为：

- 消耗院内时间；
- 不增加熟悉度、信任、好感或尊重；
- 不自动触发关系升级；
- 可以从人物专属的日常回应池中抽取文本；
- 同一时段内应避免连续抽到完全相同的回应。

因此各类互动职责为：普通闲谈提供陪伴感和时间选择；微事件积累关系并记录细节；Lv1 羁绊事件把普通同事关系变成正式羁绊；升级事件改变后续等级；认识事件只建立人物联系，不改变关系数值或等级。

现有 `locations.json` 的 `staff_ids` 只是静态展示名单。正式人物在场系统需要用数据化的固定场所、随机场所、排班／时段与当日稳定抽取结果替代这份静态名单。

### 在场判定顺序

同一人物同一时段只能出现在一个地点。建议按以下优先级解析：

1. 当前剧情或升级事件强制指定的地点；
2. 当班的固定工作地点；
3. 休息室、天台等公共场所的随机安排；
4. 不在可访问地点出现。

公共场所的结果按“日期 + 时段 + 地点”生成并保存。时段暂分为上午、午间和下午；具体边界可以继续沿用事件自身的 `time_start`、`time_end`。

建议给员工数据增加以下配置：

```json
"presence": {
  "fixed_locations": [
    {"location_id": "pharmacy", "time_start": 540, "time_end": 1020}
  ],
  "random_locations": [
    {"location_id": "lounge", "weight": 40},
    {"location_id": "rooftop", "weight": 15}
  ]
}
```

## 认识事件

认识事件只负责将 `met` 从 `false` 改为 `true`，关系仍停留在不显示等级的普通同事阶段。选项可以记录第一印象，但不改变熟悉度、信任、好感或尊重。

初始安排为：

- 神宮寺成美、七瀬恋：序章必定认识；
- 中井美佳、朝倉美幸：序章强制经过护士站时认识；
- 飯村真奈美：第一次进入药房触发认识事件；
- 深山佳織：第一次在其固定活动场所相遇时触发认识事件；
- 后续人物：由各自固定场所的第一次相遇触发。

专属固定场所首次进入时可以自动开始认识事件。多人场所则显示“上前打招呼”，由玩家逐个触发，避免连续强制播放多段介绍。

神宮寺成美的《冷掉的茶》和七瀬恋的《半份三明治》现作为首批 Lv1 羁绊事件。其他人物已经具备 `bond_01` 数据槽位，具体事件暂留空，待逐人创作。

## 互动入口与优先级

进入地点本身只解析人物在场情况。除专属固定场所的首次认识外，不自动播放关系内容。人物卡片按状态显示入口：

1. 未认识：`上前打招呼`；
2. 已认识但未建立羁绊：有 Lv1 事件时显示 `进一步了解她`，同时保留 `普通闲谈`；
3. 已建立羁绊且可升级：`进一步了解她` 与 `普通闲谈`；
4. 已建立羁绊但不可升级：`普通闲谈`；
5. 有其他地点人物事件：另列事件入口，不覆盖闲谈按钮。

看诊后、手术后等情境微事件仍由工作流程触发。地点访问型微事件改为人物卡片上的独立入口，避免进入地点时先于认识事件自动弹出。

## 手术团队邀请

所有已经认识的医护都可以被邀请进入与其团队类别相符的手术岗位；未认识人物不进入候选名单。

员工的真实职业与组队类别分开保存：

```json
{
  "profession": "pharmacist",
  "team_category": "doctor",
  "surgery_proficiency": "novice"
}
```

飯村真奈美仍显示为药剂师，但 `team_category` 视为医生，因此可以被邀请进入医生岗位。护士使用 `nurse` 类别。

`surgery_proficiency` 初步分为：

- `novice`：几乎没有手术室经验；
- `limited`：能在明确指示下协助；
- `trained`：可以正常承担岗位；
- `expert`：能主动发现问题并提供高水平协助。

选择 `novice` 或 `limited` 人物时，组队界面必须显示能力警告并播放一次人物专属确认对白。玩家确认后仍可邀请，不因能力不足被系统强制阻止。

术中对白按“具体人物优先、熟练度模板后备、通用岗位文本兜底”的顺序解析。v1 可以只改变对白和表现，不立即影响手术成功率；数值惩罚与额外操作以后单独决定。

飯村真奈美作为 `novice` 助手时使用专属紧张差分和分场景对白。被邀请、确认助手位、固定术野、正常操作回应及发现步骤异常时，台词后附不直接说出口的内心独白，突出她熟悉药品与剂量、但远离解剖和术野实践的药剂师视角。她会主动向主刀确认，不用假装熟练来掩盖不确定。

## 数据与运行时拆分

建议将人物系统拆成以下数据集合：

- `relationships.json`：认识状态、等级、熟悉度、路线和已解锁帮助；
- `staff.json`：活动场所、组队类别与手术熟练度；
- `acquaintance_events.json`：认识事件；
- `rank_events.json`：每人一段 Lv1 羁绊事件与四段升级事件；
- `micro_events.json`：关系积累与日常记忆；
- `time_events.json`：不改变关系的普通闲谈回应池。

运行时由三个独立模块负责：

- `PresenceResolver`：决定人物此刻在哪里；
- `RelationshipState`：处理认识、熟悉度封顶、升级与路线；
- `TeamEligibility`：根据认识状态、团队类别和熟练度生成手术候选。

这三个模块不直接写人物对白；所有对白继续由数据文件提供。

## 实现顺序

1. 增加 `met`、`level`、`route` 等关系状态，并让序章正确登记已认识人物；
2. 建立数据化在场解析，替换地点的静态 `staff_ids`；
3. 加入认识事件和普通闲谈入口；
4. 加入熟悉度门槛、封顶和 `rank_ready`；
5. 接入五个羁绊／升级槽位及特殊条件占位；
6. 用认识状态过滤手术团队；
7. 增加 `team_category`、手术熟练度警告和差异对白；
8. 最后逐人创作升级事件与等级帮助。

## 当前实现状态

v1 基础已接入：独立的认识状态与 Lv0 普通同事阶段、Lv1 羁绊事件、隐藏熟悉度、Lv.2–Lv.5 门槛与封顶、路线与五个事件记录槽位、固定岗位和午休随机在场、四段认识事件、普通闲谈、团队候选过滤、飯村的医生组分类，以及低手术熟练度警告和差异对白。

尚未创作的部分是除神宮寺与七瀬外人物的 Lv1 羁绊事件、每名人物四段正式升级剧情、Lv4 亲密关系内容、每级特殊帮助，以及特殊前置条件的具体判定器。数据中已保留对应字段和失败关闭的 `special_requirements` 占位，后续可逐人添加而无需再次改关系状态结构。

## Lv4／Lv5 手术室关系活动占位

所有医护都预留两项后期关系活动；它们目前只有数据定义，不提供入口，也不会改变现有手术流程。恋爱和肉体关系可并存，是否出现以及如何表现由人物专属事件决定。

- **Lv4：H 事件与手术室患者 Play**。达到亲密阶段后，依人物剧情解锁 H 事件；也可邀请她到手术室扮演患者，但不执行真实检查、术前准备或手术。
- **Lv5：完整患者流程**。达到甘愿奉献的羁绊后，人物可以真正作为患者依次经历检查、术前准备和手术；具体术式、同意过程、分支和结局尚待设计。

机器可读占位位于 `data/relationships/relationship_activity_placeholders.json`。当前所有十名医护的 Lv4、Lv5 `rank_slots` 均分别预填 `unlock_intimacy_events` 与 `unlock_clinical_practice_patient`，但在正式升级事件写入前不会实际授予。杉村弘子、朝倉美幸、深山佳織、飯村真奈美、神宮寺成美、七瀬恋、本庄萌惠和御堂江美子已经具备 `operating_patient/nervous` 立绘；中井美佳与利根川安琪仍缺少该状态素材，因此相关内容正式开放前还需补图。
