# 术中危机系统实现

实现依据为 `docs/design/HOSHIMI_SURGERY_FAILURE_AND_CRISIS_SYSTEM_V0_1_2026-10-04.md`。普通手术的唯一通用生理失败入口是 `physiologic_crisis`；尊严、配合度和术野不进入这套随机失败公式。

## 运行流程

正确完成一个手术节点后，系统按麻醉路线、节点生理压力、恐惧、痛苦、稳定度和失血计算 2%–30% 的危机概率。全身麻醉不计清醒患者的恐惧与痛苦。节点可显式提供 `physio_stress: low|medium|high`；缺省时根据节点位置和现有提示推断。

危机发生后暂停节点推进，提供三种处理：暂停操作并稳定患者、保持术野让团队处理、先完成关键动作。2026-10-14 共享候选规则采用常规危机 90/75/60、严重危机 80/60/40 的基础成功率，再叠加原有团队与选项修正，最终限制在 5%–99%。每次选择和随机点数都写入事件日志，同版本规则下重放得到相同结果；当前格式的存档直接恢复快照。

危机触发时还会从锁定的八类生理表现中确定一个 `flavor_id`，由当前巡回护士在原有记录框内报警，同时保留全部处理按钮。症状、发言护士和台词变体都由该节点已有的 `crisis_roll` 确定；第一次处理失败后不会改抽另一种危机，而会沿同一条台词升级到第二级，第二次失败后升级到第三级。没有可用巡回护士或人物专属台词时使用通用巡回护士播报。该层只负责演出，不修改危机概率、严重度、处理成功率、时间或结算。

三次补救均失败时，追加支援稳定患者并中止手术。患者不会死亡；该台手术不计完成次数，不获得手术经验或解锁进度。消耗的手术时间与危机处理时间保留。

## 玩家开关与持久化

主角办公室提供“术中危机事件：开启／关闭”。关闭后只跳过通用随机生理危机和由此导致的中止；患者互动、CG、Fear、Pain、Dignity、Cooperation、Visibility、Blood Loss、Stability、Progress 和 Time 均继续运行。

开关默认开启，并同时保存在 `user://settings.cfg` 与游戏存档快照中。旧存档缺少该字段时按开启处理。

### 普通术式节点数值波动

仅作用于现有 `pilot_surgery()` 的 30 台普通术式。F/L/S 从术式阶段的显式 `risk_class` 静态元数据读取，不能按选项数量推断；其中 17 个 S 类阶段只有 A/B 两个选项，仍使用 S 的 1.2% / 3.0%。A/B/C 顺序经过设计原文、效果与运行时选项 ID 的逐项映射核验，不改写实际选项 ID。条件修正节点按本次候选设计明确使用 L 档，不由选项数推断。全体选项均须为正确操作；缺失/非法分类时不接入该层，不猜测回退。映射证据见 `docs/qa/calibration_20261014_v2_identity.json`。

每次正确操作按以下顺序执行：原有主效果 → 原有顺序条件效果 → 小波动并截断到非负 → 大波动并限制数值范围 → 原有生理危机判定 → 原有反馈及患者互动。噪声分母为全部原始节点数（含条件修正节点），不是实际走过的节点数。

- 小波动：独立均匀随机数 U，时间增量 `(2U-1) × 0.23 × ET / 节点数`，失血增量 `(2U-1) × 0.14 × EB / 节点数`。
- 大波动触发率：F 0.3%；L 的 A/B 为 0.6%/1.7%；S 的 A/B/C 为 1.2%/3.0%/11.5%。骰点严格小于概率才触发。
- 大波动强度为 0.72，种类分界为 0.62 / 0.88；三类只影响现有时间、失血、出血、视野、稳定度，其精确公式和取整测试见上述规则文件与 `tools/surgery_numeric_calibration_test.gd`。
- 不直接新增并发症、状态标记、F 级失败或患者四项数值变化；波动后的失血／稳定度可影响既有生理危机判定和评分，这是预期的间接影响。

工程现有状态为整数，对每一个增减量分别 `roundi` 后再走既有数值限制。离线模拟使用浮点累计，因此不能声称逐例或概率分布与 ZIP 完全相同。ET/EB 沿用当前运行时基线；逐术式主效果、条件效果及其 817 条候选补丁均留待下一阶段审核。

这里的时间是原有 `procedure_state.elapsed_time` 技术评分指标，与既有 strategic_effects 一样处理；不额外改变医院日历的时间结算方式或重复扣时。

### 骰点、读档和关闭危机的行为

实时入口 `app.preop_event()` 为符合范围的 surgery_step 增加 7 个 `variance_rolls` 整数骰点（0–999999）。它们来自独立 RNG，以现有 surgery_rng_seed、术式 ID、节点 ID 和版本命名空间确定；同节点不同选项使用同组骰点，不消耗危机或患者互动的全局随机流。

事件日志携带骰点，实际骰点和已取整效果写入现有 `resolved_random_choices`，沿用现有快照存档，不新增游戏状态字段。读档恢复后下一节点继续使用同种子序列。旧事件缺少 variance_rolls 时不补抽；旧事件中的救援仍由当前版本救援曲线解释。重复点击及非法骰点在产生任何状态变化前拒绝。

关闭“术中危机事件”仅关闭既有生理危机：数值波动继续运行，不独立触发失败；一键扫荡不经过逐节点流程，因此不抽节点波动。
