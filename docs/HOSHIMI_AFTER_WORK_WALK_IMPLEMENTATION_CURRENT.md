# 下班同行：当前实现与原稿差异

核验日期：2026-10-26。代码基线：`f95636a22b16c7d2dfd99e9956e32c90b3dba21e`。

本文记录当前代码实际行为，供维护和验收使用；不代表用户已经批准所有偏离原稿的行为。本次只更新文档，不调整游戏规则。

2026-10-05 原始设计已逐字归档为 [HOSHIMI_AFTER_WORK_WALK_IMPLEMENTATION_V1.md](source/HOSHIMI_AFTER_WORK_WALK_IMPLEMENTATION_V1.md)。原稿保留历史设计和原始台词，不能直接作为现行实现说明。持久化以 [v37 安全边界存档契约](save_boundary_v37.md) 为准。

## 1. 时间、触发与收益

| 项目 | 当前实现 |
| --- | --- |
| 门诊停止接收新患者 | 16:00；已有诊疗流程不被截断 |
| 主动结束工作日 | 16:00 起，仍受诊疗、住院、预约及事件等状态限制；周日不走此入口 |
| 深夜分界 | 离院时钟达到 19:00，使用 `night`；之前为 `normal` |
| 正常时段不出现邀请 | 20%，即存在候选人且其他条件满足时有 80% 出现邀请 |
| 深夜不出现邀请 | 40%，即存在候选人且其他条件满足时有 60% 出现邀请 |
| 同角色冷却 | `AFTER_WORK_COOLDOWN_WORKDAYS = 2`；D 日出现后 D+1 排除、D+2 可再出现 |
| 冷却起算 | 出现邀请时记录，拒绝同行和玩家跳过也占用；深夜没有豁免 |
| 正常同行收益 | 固定熟悉度 +2 |
| 深夜同行收益 | 固定熟悉度 +4 |
| 拒绝／跳过 | 熟悉度 +0 |
| 上限 | 熟悉度上限 100，界面显示实际增加量 |
| 额外耗时 | 同行本身不另加分钟，由离院流程执行换日 |

冷却比较的是传入的游戏日序号差，不是专门跳过周日的“工作日历”。常量虽名为 `WORKDAYS`，也不能据此解释为“三天冷却”。

邀请出现概率与角色接受概率是两个独立步骤。当前接受概率只看关系等级，没有按性格配置不同公式：

| 等级 | Lv0 | Lv1 | Lv2 | Lv3 | Lv4 | Lv5 |
| --- | --- | --- | --- | --- | --- | --- |
| 正常：`min(95, 65 + level × 7)` | 65% | 72% | 79% | 86% | 93% | 95% |
| 深夜：`min(99, 90 + level × 2)` | 90% | 92% | 94% | 96% | 98% | 99% |

触发、候选人选择和接受判定使用 `campaign_seed`、离院日、时段及不同 salt 的哈希。相同输入下结果确定；候选列表先按 ID 排序。它不是每次重绘界面都重新抽奖。

## 2. 候选人范围

`GameState.after_work_candidates()` 的实际筛选只有：

- 有有效角色 ID。
- `staff_is_met()` 为真。
- 档案 flags 不含 `after_work_disabled`。
- 达到上述同角色冷却间隔。

当前没有进一步核对性别、职业、在岗／排班、当日共同工作记录，也没有要求逐角色显式启用。正常与深夜使用同一候选池。

当前加载的 28 名医护中，档案显式禁用同行的是 `doc_serika` 和 `doc_takemi`。其余 26 名只是潜在候选，实际仍需相识和冷却条件。原稿要求排除的 `nurse_ishigami`、`doc_sakura_anesthesiology`、`visiting_maya`、`visiting_futaba` 目前没有该禁用 flag，因此相识后可能入池。这是原稿与代码的差异，不是本文新增的开放决定。

## 3. 离院与演出流程

主界面的 `request_end_workday()`／`show_day_transition()` 负责离院事件优先级及换日。专属离院事件、当天已接受的预约等先于普通同行；不能绕过待处理临床流程启动同行。

`begin_after_work_departure()` 在以下情况拒绝开始：

- 已完成的特殊事件声明 `skip_departure_events_on_completion`，例如小夜香 Lv5 Part A／B。
- 存在正在执行的预约离院流程，或当天预约仍待处理。
- 门诊、已承诺或进行中的手术、未解决的住院患者仍需处理。
- 已在同行、特殊事件、人物事件或微事件中。

住院交接后的结束工作日另有 `can_end_day_after_admission()` 入口，要求 17:00 起且交接状态满足条件。它不意味着允许绕过 `begin_after_work_departure()` 的患者检查。

出现邀请后，玩家可邀请或跳过；邀请再判定接受或拒绝。接受时立即结算熟悉度并切到结果阶段；之后的聊天、告别和页面刷新不再次发奖励。当前阶段检查也会阻止重复执行同一邀请选择。

同行在内存中保留离院所属日与离院时钟，由结束流程统一换日，避免夜间手术后丢失原离院日或重复前进一天。此内存上下文不是存档字段。

没有单独持久化的“今天所有同行机会已用完”总开关。正常 UI 依靠一次离院流程和当前会话防重；固定哈希也不等于对所有入口的全局幂等保障。若以后增加可重复调用的离院入口，需要另行验证当日拒绝、跳过及未出现邀请后的行为，不能宣称已有完整的全局每日一次防护。

## 4. 台词、背景与服装

- 角色短聊读取 `after_work_short_chat`；其他同行环节读取 `after_work_companion_dialogue[kind]`。
- 角色／离院日／环节决定台词数组下标；缺少角色台词时由界面使用通用回退。
- 当前没有原稿中完整的性格 × 关系阶段台词分派及六类性格接受率表。
- 接受同行后的结果演出使用街景；邀请或拒绝阶段仍使用医院大厅／医院夜景。
- 季节按离院日期月份：3–5 月春、6–8 月夏、9–11 月秋、12–2 月冬；19:00 起选择夜景。
- 背景查找顺序：`after_work_street_{season}_{day/night}` → 对应季节 → 对应时段 → 通用街景占位 → 医院夜景。资源映射在 `data/backgrounds.json`，目前包含四季街景和对应夜景。
- 9–2 月优先使用角色存在的 `casual_winter/neutral`；随后按已有的 `after_work`、`casual`、默认／制服资源回退。服装按离院日期解析，邀请及结果阶段均适用。
- 尚无实际天气驱动的同行分支；不应把原稿的天气扩展设想描述为完成。

## 5. 存档边界

只能在医院导览／周日安全边界保存。同行中的邀请阶段、结果、对白页码、待确认选择、离院演出上下文均只在内存，不写玩家存档。

可以保存的是已结算熟悉度、关系中的最近邀请日事实（`after_work_offer_day:<day>`）、种子、已结算时间等持久数据。读取安全边界存档不恢复半段同行，也不重发奖励。原稿要求保存同行进行状态的方案已经被 v37 契约取代。

## 6. 与原稿及旧对话的关键差异

| 原稿／旧记录 | 当前代码 | 维护结论 |
| --- | --- | --- |
| 原稿正常／深夜出现率 35%／70% | 80%／60%，等价于不出现率 20%／40% | 不可混淆“出现”与“不出现” |
| 原稿深夜 22:00，且须有晚间实际手术及共同加班依据 | 19:00，仅由离院时钟分流 | 原稿的手术／在岗资格判定未实现 |
| 旧对话称同角色三天冷却 | 数值 2，D+2 可再次出现 | 三天规则尚未在当前代码体现 |
| 原稿两工作日冷却、深夜豁免 | 游戏日序号差 2，深夜同样受限 | 不以常量名称推断工作日历 |
| 原稿逐角色资格及排除表 | 相识、禁用 flag、冷却筛选 | 角色范围存在差异，见第 2 节 |
| 原稿按六类性格决定接受率 | 统一等级公式 | 个性化概率表未接入 |
| 原稿全局每日一次（含未出现） | 单次 UI 流程及会话检查，没有完整全局标记 | 新入口需验证，不靠持久化演出状态补齐 |
| 原稿保存进行中的同行状态 | v37 仅保存稳定事实 | 原稿的中途恢复设计不再适用 |
| 原稿季节背景留作后续 | 四季及夜景、冬季便服已接入 | 属于已完成的扩展 |

这些差异需要在未来改规则时明确选择；本次没有把历史设计强行写回代码。
