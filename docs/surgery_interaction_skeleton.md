# 手术室互动骨架

当前版本把手术室内容接在术前确认之后，重点验证操作者与患者之间的选择和反馈。它不是具体手术模拟，也不提供现实医疗操作指导。

团队确认后先从 `surgeries.json` 选择术式，再选择麻醉。主刀发出开始手术与“手术刀”指令后，器械护士递刀、助手固定切入部位，玩家确认下刀。清醒患者随后进入术中互动；全麻患者不再出现语言回应。关键步骤完成后以“手术成功，现在缝合”结算，并进入适用的手术 CG。

若麻醉前所选术式 ID 与病例的 `surgery_id` 不同，流程进入独立的患者惊愕对白页，增加40点恐惧并写入 `wrong_procedure_selected` 标记。玩家确认重新说明后才进入麻醉准备。暂时不追加纠正、取消、事故或失败分支。

手术完成页使用统一描述：“术式历时多久，顺利完成。患者姓名的状态暂时平稳。” `postoperative_state_text()` 当前固定返回占位状态“暂时平稳”，以后在这里根据生命体征、恐惧、痛苦、尊严和配合度选择不同描述。

后续可让错误术式触发团队成员的特殊反应：发现错误、质疑主刀、安抚患者或事后冲突。该分支需要结合岗位、人物性格和关系系统，本阶段只保留患者反应与错误标记。

## 当前流程

```text
团队最终确认
  → 选择麻醉状态
    → 主刀命令开始手术
      → 未麻醉患者提出异议（可返回重选一次，或坚持继续）
      → 器械护士递交手术刀
        → 助手固定切入部位
          → 玩家选择下刀
            → 从6张通用女性手术团队CG中随机切换术中背景
            → 清醒患者出现麻醉对应反应 / 全麻患者无语言反应
              → 术式步骤 1：术野确认
                → 清醒患者第一次术中回应
                  → 术式步骤 2：团队配合
                    → 清醒患者持续回应
                      → 术式步骤 3：关键判断
                        → 清醒患者结束前回应
                          → 术式步骤 4：完成复核
                            → “手术成功，现在缝合”
                              → 手术结果与适用 CG
```

麻醉选择包含全身麻醉、硬膜外麻醉、局部麻醉和未麻醉四个原型分支。全身麻醉在诱导后固定配合值，并连续执行四个团队步骤；硬膜外、局部与未麻醉分支根据每个步骤的互动主题、身体感受、术式类别和患者四项指数匹配患者事件。未麻醉患者开始前会先询问或抗议；玩家只有一次返回麻醉选择的机会，坚持继续则触发患者情绪崩溃。清醒分支让操作者在手术推进过程中通过解释、暂停、安抚、简短指令或沉默影响患者。

## 术式专属团队流程

`surgeries.json` 中现有 25 种术式各自包含四个叙事阶段：术野确认、团队配合、关键判断和阶段完成。

- `confirm`：只有一个继续选项，用于推进术式专属步骤并触发团队对白。
- `flavor`：三个选项都不会改变手术结果，分别向助手、器械护士或巡回护士确认信息。
- `decision`：三个选项中只有一个正确。错误选择由助手立即指出问题并说明应核对的内容，然后继续手术；当前不会触发事故。

每次选择写入 `procedure_step_history`，错误判断数量写入 `procedure_corrections`。将来可以在错误选项上增加事故 ID、生命体征变化或突发事件入口，同时保留现有内容结构。

确认下刀时，界面从空手术室与单人状态图切换到 `operating_team_01` 至 `operating_team_06` 的通用术中背景池。选中的背景 ID 直接写入下刀事件，因而同一台手术的后续步骤、团队回应和存档回放始终使用同一张图。术式选项页使用虚化、压暗的团队背景与独立深色选择面板；团队成员作出回应时，在右侧显示实际回应者的无菌服立绘。患者或旁白回应先显示在独立确认页，点击继续后清空记录，再显示下一组术式选项。

每个术式阶段的 `awake_interlude` 指定互动主题，`patient_cues` 指定患者可能感到的切开、压力、牵拉、深部操作、暴露、疲劳或关闭切口等线索。运行时优先匹配具体术式对白，再匹配 `procedure_group` 类别对白，最后回退到通用池；每层内部结合恐惧、痛苦、尊严和配合状态。患者事件留在 `surgery_flow` 内部，不离开团队流程；全麻分支全部跳过。

## 状态值

- **恐惧**：越高越容易进入惊恐表情，并在 80 以上削弱配合。
- **痛苦**：越高反应越强，并在 75 以上削弱配合。
- **尊严**：代表患者感到自己是否被尊重；25 以下会额外削弱配合。
- **配合**：由基础配合与临界值惩罚共同计算。清醒患者在跨过临界点以前可以维持较高配合，跨过后会明显下降。

每次选择直接改变这些状态，患者立绘会在清醒、紧张、害怕和麻醉中自动切换。最终页根据状态组合给出一段互动总结。

## 数据与扩展点

动态术中互动和数值效果位于 `data/surgeries/patient_interactions.json`；术前及麻醉结构位于 `data/patients/templates/preop.json`，患者专属提示位于各自 `patient.json` 数据包；运行状态位于 `godot/systems/preop_session.gd`；界面位于 `godot/ui/preop_view.gd`。`show_if_flags` 与 `hide_if_flags` 控制麻醉专属选项及一次性反悔选项。手术开始以后禁止写入存档，完成手术后恢复保存。

后续可以在同一节点上增加人物性格修正、患者专属台词、医生或护士担当患者时的特殊反应，以及术后交接。性格系统只需在呈现台词和结算效果时读取角色标签，不必重写现有流程。
