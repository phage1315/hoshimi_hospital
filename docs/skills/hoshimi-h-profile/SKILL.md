# 星见角色 H Profile

把用户提供或已确认的角色正文、偏好和素材接入现行共用 Runner。输出技术配置与可核查的缺口，不自行续写角色正文。本技能不授权发布、外传素材、提交、推送或改玩家存档。

## 开始前

1. 定位用户指定仓库；未指定时从当前目录识别 `project.godot`、`godot/systems/free_h_registry.gd`。读取本地 `agents.md`／`AGENTS.md`，检查 Git 状态。只修改本次角色及必要共用接口。
2. 检查角色当前注册、原稿、候选与正式素材、导入清单、测试记录。已有授权和已提供的素材继续使用，不重复索要。年龄与身份取项目数据，不凭外观推断。
3. 本技能基线为2026-10-29的芹香独立头像方案；执行时检查现行代码。优先阅读 `free_h_registry.gd`、`h_profile_v1_content.gd`、`h_profile_v1_session.gd`、`scene_content_context.gd` 及 `app.gd` 对应 UI。若契约已变化，按实际版本调整，不能为了套模板退回旧行为。

## 按任务选择工作

- **规划新角色／列作者缺口**：读 [作者清单](references/author-inputs.md)，用 [intake.template.json](assets/intake.template.json) 整理已知、待确认、缺失三类信息。仅询问无法从仓库及对话确定、且影响实现的问题。
- **生成技术草稿／处理原稿包**：读 [数据契约](references/data-contract.md)。`assets/` 中四份运行数据模板均是明确未就绪的空白结构，不能直接放入正式加载路径；没有作者输入的正文保持缺口。已有用户 JSON 优先原样归档并通过适配器接入，不强行改成模板形式。
- **补图／资源接入**：按用户明确的文件→角色→槽位映射原样复制；确认尺寸、Alpha、SHA256和资源路径。纯导入不主动进行视觉内容审查。热区标定或图片评价仅在用户要求时开展。每次补图后重新枚举全部槽位，尤其检查“已提供但尚未导入”。
- **接通／验收**：读 [验收流程](references/integration-qa.md)。素材齐全只是必要条件；正文、英文、资源、生产流程和边界均通过后再设 `ready`。

## 作者必须提供的NSFW基础图片

明确向作者列出四类交付：**触摸底图（body_map）、第二阶段sex图（scene_cg）、事后CG（aftercare_cg）、六种头像中的neutral基准图（portrait_neutral）**。优先复用作者已提供并指定的文件，不重复索取。若作者提供的 NSFW 立绘／头像为非透明原图，直接调用本地离线 `.venv/bin/python tools/portrait_matting.py --resize-mode keep`（见 [立绘与本地透明化管线](../hoshimi-portrait-pipeline/SKILL.md)）完成神经网络去背景，严禁外传云端或使用颜色阈值脚本硬抠。

另外五种头像为annoyed、pleased、flustered、delighted、peak。经用户授权后：若请求可由绘图工具（imagegen）正常处理，优先由绘图工具直接生成完整表情差分并经 `tools/portrait_matting.py` 本地透明化；**若绘图工具拒绝处理（如 NSFW 立绘差分）**，则在已透明化的 `neutral` 基准图上采用本地局部面部修改／合成方案制作差分（或按用户决定交由作者提供）。保持作者确认的构图，不为继续生成擅自裁切或更换构图。最终仍须六种头像齐全才算素材完成。

## 关键边界

- 区分“用户内容包版本”“Profile schema”“Flow patch”“Context版本”。不能把文件名中的V1.1写成Profile schema，也不能用旧V1 Schema的通过结果代替现行适配器验证。
- 用户正文、说话人、顺序、标点原样保存；如需英文，先复用已授权翻译或已有译文。翻译不得扩写、改变语气或引入原文没有的内容。无法处理的具体片段保留原稿并准确报告，继续不受影响的技术工作。
- 本技能生成结构、字段映射和中性占位；不生成露骨色情对白、场景或图像。已有素材的本地技术集成与新内容生成分开处理。
- 角色偏好由用户定稿；可解释已存在的数值规则，但不从人物性格擅自断定偏好。不把“低偏好”解释成拒绝机制；现行Runner没有这种机制，若用户需要须另议实现。
- 使用角色自己的底图、头像、CG和背景。小夜香图集的专用分支不能靠换角色ID复用；新角色默认独立六头像。
- 不改写固定Lv4剧情来适应重复互动，不将剧情专用对白自动注入重复流程。新角色剧情回调未实现时不得声称只靠配置即可支持。
- 存档仅在医院导览和周日安全边界；预约只存稳定业务事实。事件步骤、反应历史、选择路径、台词进度、临时style与MAX状态只驻内存，不写玩家或测试存档。
- 不因缺素材而借用别人的图、制造已完成前置或取消门槛。缺口存在时保留 `pending_assets`，分别报告“内容就绪”“资产就绪”“生产流程已验收”。

## 辅助检查

运行 `scripts/inventory.py --repo REPO --profile PROFILE --context CONTEXT --bodymap BODYMAP`：只读枚举该角色资产、缺失文件、PNG尺寸和摘要，检查基础映射。支持 `--source-manifest MANIFEST` 对照本技能格式的导入清单。它不读取对白全文到输出，也不替代Godot、英文审计或视觉验收。

必须以现行Godot适配器和Registry实际加载为最终依据；辅助脚本通过不能自动设ready。
