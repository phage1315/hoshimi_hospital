# 作者需要决定或提供什么

这是用户填写清单。已存在于项目或对话中的最终决定直接引用；不要求重新提交。可以先提供自然语言或Markdown表，由助手转换字段，不要求用户手写JSON。

## 一、内容设计决定

| 项目 | 需要的信息 | 来源与处理 |
|---|---|---|
| 身份 | 稳定actor_id、姓名、成人身份、项目角色档案 | 优先读项目数据；缺少事实才请用户补充。不能把模板的adult_confirmed自动设true |
| 关系背景 | 当前关系阶段、称呼、语气、避免使用的措辞 | 用户最终稿或已确认设定；不要盲目将“医生”替换成人名 |
| 解锁条件 | 真实完成事件ID、character_event或special_event、既有亲密资格、额外flag（若有） | 必须能对应真实实现；只有等级数字不够。没有真实前置时入口锁住 |
| 场所 | 选定一个正式重复地点、显示名、邀请回应、背景 | 现行正式Registry每人一个location_id；多个文本地点池不等于多个地点可玩 |
| 入场策略 | 按序播放全部入口句，或每次随机一句 | 使用entry_random_one；不把芹香的“四选一”当所有人的硬性规则 |
| 偏好表 | 九区默认档位、动作覆盖、特定组合覆盖 | 用户决定low/mild/strong/favorite；可先只填九区默认，覆盖表为空 |
| 风格与流程 | 接受共用的两个style及现行阶段流程，还是另有明确设计 | 新机制单列范围；不能靠无效JSON字段假装实现 |
| 原稿版本 | 哪份为最终稿、哪些修改获授权、是否授权英文翻译 | 归档原件；不擅自改写标题、正文、说话人或顺序 |

现行偏好数值是全局规则：low +2、mild +6、strong +12、favorite +18，最高100；对应默认表情annoyed／pleased／flustered／delighted，达到100显示peak。它们不是人物单独可调的JSON值。调整全局规则属于另一个明确任务。

## 二、必须有作者依据的文本

所有角色专属文本由用户提供最终稿，或从该角色已获授权的原稿复用。助手负责整理、逐句比对及获授权的翻译，不自动创作缺失正文。

| 文本 | 当前接口数量／要求 | 是否每个新角色必须新写 |
|---|---|---|
| 预约邀请回应 | 正式地点1句；另有中英地点名 | 应有自己的原稿；可由用户明确批准复用 |
| 入场 | 实际注册地点至少1句；用户决定多句与选取策略 | 必须有；未开放地点无需强制补池 |
| 通用反应 | low/mild/strong/favorite各非空池，确保所有组合有回退 | 必须完整覆盖；每池4句是芹香示例，非现行硬门槛 |
| 更具体的反应 | 区域×档位、动作×档位、动作×区域覆盖池 | 可选；已有36组合全部可回退，不必各写一套 |
| 阶段池 | scene.start、scene.middle、scene.finish各3句 | 当前Session要求；finish在1.3.4保留但不自动播放，不伪造占位来过验证 |
| MAX提示 | 1句 | 必须有 |
| style开场／中点 | 两个style各开场1句、中点1句，共4句 | 必须有 |
| 手动完成回应 | 4句，抽1句，回应确认后结束阶段 | 必须有 |
| 事后 | 2句，按顺序 | 必须有 |
| 选项与按钮 | 两个style标签；全局结束按钮5种标签已有 | 未要求改动时引用现行共享标签；不复制成新角色私有协议 |
| 英文 | 覆盖上述正文、显示名、选项及所有保留池 | 用户供英文，或明确授权翻译；中文通过不表示完成 |

源文可能以字符串或反应对象提供，具体结构见数据契约。不得要求所有人物凑齐芹香70句Profile／86条审阅记录；数量必须从该人物真实输入计算。

## 三、作者必须提供的NSFW图片与差分分工

**作者必须提供或明确指定已有文件的四类NSFW基础图片：**

1. **触摸底图**：`body_map`。
2. **第二阶段sex图**：`scene_cg`。
3. **事后CG图**：`aftercare_cg`。
4. **六种头像中的neutral基准图**：`portrait_neutral`，作为其余表情的角色外观与构图基准。

作者已经提供的文件直接列为已收到，不重复索取；原样接入，不擅自替换为SFW图或其他角色素材。

**其余五种头像差分**：`annoyed`、`pleased`、`flustered`、`delighted`、`peak`。用户授权且请求可由imagegen处理时，助手可以根据neutral制作；**imagegen无法生成时，由作者提供对应缺失差分**。保留已确认的构图，不自行裁成只有脸部的替代版本；若确需改变构图，先取得具体授权。最终交付仍为六种头像，不能用neutral代替缺失表情而宣称齐全。

| 槽位 | 提供方／实际要求 | 推荐交付规格 |
|---|---|---|
| body_map | 作者提供最终NSFW完整底图；确认是否授权标定点击区域 | PNG，推荐2:3竖图1024×1536或2048×3072；实际宽高写入Context与热区文件 |
| portrait_neutral | 作者提供NSFW头像基准图 | 真透明PNG，建议方形画布；1024²／1280²均可 |
| 其余五种头像 | 可在授权及可处理范围内由imagegen制作；无法生成时作者提供 | 与neutral保持相同构图、相近头部比例位置，优先统一画布；必须是真透明PNG |
| scene_cg | 作者提供第二阶段sex图 | 横向清晰PNG；现行框940×500采用contain，不强制16:9或拉伸 |
| aftercare_cg | 作者提供事后CG | 同上；可经作者明确指定复用自己的已批准CG |
| background | 可复用已批准背景，或另行委托制作SFW背景 | 正式地点的背景ID与文件；需要不同时间氛围时明确选择对应版本 |

现行界面：底图框340×510；互动头像400×392，入场头像300×300；窗口设计1280×800。尺寸是布局基线，执行时查代码。

上述四类NSFW基础图由作者提供；其他素材的分工按上表执行。露骨性图像仅做获授权的本地技术接入，不由本技能生成。使用imagegen处理可处理的头像差分或SFW背景需要对应授权；纯本地导入无需向第三方发送素材。

棋盘格不等于透明：核验Alpha，不能仅看扩展名或聊天预览黑底。不要擅自抠图、裁切、修白边、统一分辨率或改Alpha；发现问题报告具体技术影响，修改需用户授权。

## 四、助手可以直接完成的工作

- 从现行代码提取字段、生成未就绪草稿、解析用户表格，计算完整4×9偏好矩阵并请用户审阅设计决定。
- 已指定文件原样复制、命名、SHA256清单、引用与尺寸核对；补入用户明确提供给该角色槽位但遗留未接入的文件。
- 用户要求热区分析时按最终图标定多边形，并计算归一化坐标；不能移植别人的坐标。
- 获授权的英文翻译和逐句审阅、运行现有适配器、专项测试、正式预约和存档边界验证。
- 用状态表区分：未提供／已提供待导入／已导入待验证／已验证。不要因为前一份missing清单过时而再次向用户索图。

不需要用户手工提供：Godot代码、PNG导入缓存、热区数值（已授权分析时）、校验和、测试脚本、适配器规范化后的schema1数据。
