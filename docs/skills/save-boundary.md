# 安全边界存档变更工作流

权威约束是根 AGENTS.md，现行实现契约见 [save_boundary_v37.md](../save_boundary_v37.md)。不得因新功能需要中途恢复而扩大存档范围。

1. **先分类。** 对拟新增字段逐项说明：持久数值、稳定业务事实，还是临时会话状态。节点、页码、步骤、选项路径、最后台词、待确认、随机演出上下文和重放日志永不写入恢复游戏的文件；事件已完成也不例外。
2. **设计事实。** 保存稳定事件 ID／完成日／必要次数或结果、已结算时间和数值。分支效果转为独立语义 flag；预约、住院、队列只保留业务必需字段。不要把整个 Session 或任意扩展字典写入白名单。
3. **核对入口。** 查看 `GameState.can_save_progress()`、`snapshot()`、`BoundarySave.capture()/restore` 的现行接口以及 `SaveStore`。医院导览和周日以外必须拒绝保存；运行时语言切换使用内存快照，不落盘。
4. **迁移。** 旧档只提取可靠事实；总时间以实际已结算值为准。旧节点删除不应使整档拒绝；不要重放来推导过去。无法可靠恢复的业务值报告并确认，不静默清空或补发奖励。
5. **隔离测试。** 先读测试脚本写入目标，使用独立临时目录／槽位。原生 fixture 只在内存制造前置；不修改玩家文件，不把事件中间快照叫作测试存档。
6. **验收矩阵。** 覆盖安全边界准入／拒绝、持久 JSON 无内部状态、节点重命名／删除后仍可恢复、时间与数值不变、奖励只结算一次、再次保存读取稳定，以及失败读取不替换当前游戏。新增业务事实还需测试非法值与缺失兼容。
7. **报告。** 区分“规则已记录”“实现已修改”“哪些测试通过”；不能以文档更新代替迁移。v37／v36 的现行兼容边界不可未经核验扩展到所有历史档。

测试入口见根 AGENTS.md 的存档行；至少按改动覆盖 `boundary_save_test.gd` 与相关事件锁定、历史耗时和 SaveStore 文件 I/O 测试。实际执行结果必须附本次日志，不预先宣称通过。
