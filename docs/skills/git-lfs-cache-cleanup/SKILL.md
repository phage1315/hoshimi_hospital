# 上传后清理 Git LFS 缓存

用户偏好：保留 GitHub 上的 LFS 对象和项目工作目录中的实际素材，不长期保留多余的本地 LFS 对象缓存。Git LFS 在 add、checkout、pull 等操作中仍可能重新生成缓存；本技能不是禁用缓存的配置，也不是后台任务或 Git hook。

《星见医院》仓库 `/Users/ningye/Documents/Codex/2026-09-20/wo/outputs/hoshimi-hospital` 已获持续授权：在用户授权的 push 成功且以下检查通过后，清理已上传的 LFS 缓存，无需重复询问。其他仓库须由用户调用本技能或明确授权清理。该授权不包含自行提交、推送、修改剧情素材或向新远端上传。

## 检查与执行

- 确认真实仓库、远端、Git 目录及 `git lfs env` 中的 LocalMediaDir；检查 worktree、stash、分支和未提交状态。若 LFS storage 与其他仓库共享，停止清理该存储并说明原因。
- 用实时远端查询核对已推送的提交，不能只信本地 origin 跟踪分支或“push 成功”。以 `git lfs ls-files --json` 枚举当前文件，验证工作目录中是实际文件且 SHA-256 与对应 OID 一致；只做技术校验，不查看图片内容。
- 保护未提交的新素材、修改和缺失文件。除非用户已明确授权删除该文件，缺失不能当作正常；若无法判断是否会损失恢复能力，保留相关对象并报告。历史版本不要求在当前目录同时保留，但其待清理 LFS 对象必须在远端验证存在。
- 执行前后记录工作区状态与保留的工作文件哈希。不要在 add、checkout、push、其他代理编辑或 LFS 传输正在进行时清理；状态变化后重新核验。
- 先阅读本机 `git lfs prune --help`，确认选项语义。使用预演：

```bash
git lfs prune --dry-run --force --verify-remote --verify-unreachable --when-unverified=halt
```

- `--force` 在这里仅用于把当前检出版本的缓存也列入清理，不允许省略远端验证。检查预演是否保留未上传对象、是否出现远端缺失或校验失败；有失败则保留缓存并报告，不以 `rm -rf` 绕过。
- 预演通过且工作目录验证通过后，使用同一组参数移除 `--dry-run` 执行。该命令再次验证远端后才删除对象。不要上传缺失对象来强行满足清理条件，除非用户另有上传授权。
- 只清理 LFS 对象缓存；保留 `.git`、索引、refs、reflog、hooks、配置及项目素材。不运行历史重写、reflog expire 或 Git 对象 prune。允许缓存根目录作为空目录保留。
- 核对缓存剩余大小、保留工作文件的哈希及工作区状态，报告实际清理结果。说明后续恢复或切换版本可能需要联网下载。

无法在 GitHub 确认的孤立对象不自动删除；只在用户明确同意丢弃具体对象集合后另行清理。不要把 Git 缓存清理扩大为 `.codex` 聊天、测试截图或其他目录清理。
