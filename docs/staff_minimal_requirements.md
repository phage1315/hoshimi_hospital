# 星见医院：新增医护人物 Minimal Requirements

版本：2026-10-13。适用于基础人物批量接入；具体代码门槛以接入时的 schema 和验证器为准。

## 1. 分工与最小交付原则

- **用户提供人物信息、原始种子图，以及剧情原文或明确的创作授权。** 人物身份、性格、能力定位、关系与出场设定不得由 Codex 擅自补全。
- **Codex 整理缺口，与用户协商美术素材清单，调用 imagegen 分批制作，再完成数据、英文和运行时接入。** 用户无需自行准备整套成品图或 JSON。
- 必填项可以明确填写“本批不开放”或“待定，先不实装”，不能留空让 Codex 推断。基础身份、可识别外貌及本批实际启用功能所依赖的信息，必须在实装前确定。
- 未提供完整成长路线不妨碍先接入基础人物；未完成的剧情与功能应标记为计划中或不可用，不能伪装成已完成内容。
- 已有授权继续有效，不重复征求确认；本模板中的空白与未勾选项不构成授权。

## 2. 用户必填：人物信息与剧情需求

复制以下表格，每人填写一份。可以引用已提供的文档，但需明确对应角色与版本。

### 剧情与对白授权（填写适用项，不默认授权）

- 用户提供原文：`文件／附件：________`。按原句、说话人、顺序及标点接入。
- 允许 Codex 补写基础工作对白：`是／否；范围：________`。
- 允许 Codex 创作初见事件：`是／否；用户指定提纲与条件：________`。
- 允许 Codex 创作日常互动：`是／否；范围：________`。
- 允许 Codex 创作关系或其他专属剧情：`是／否；具体片段与边界：________`。
- 本批没有原文也未授权创作的内容：`________`，暂不实装。

岗位已启用时，必须解决其实际使用的对白：采用何种通用规则、使用用户原文，或授权补写。巡回护士需覆盖危机报告；专属护士需确认诊室辅助及术前说明；经验不足的医生需体现其经验限制和接受纠正的回应。

### 专属护士必需：两句诊断纠错对白

适用于 `profession: "nurse"` 且 `personal_nurse.eligible: true` 的角色，包括以后新增的专属护士。每人必须提供以下两句有个人口吻的中文原文或明确的创作授权，并同步完成英文翻译；没有原文或授权时报告缺口，不得用通用占位句充数。

| 必需对白 | 使用场景 | `profile.json` 中的字段 |
| --- | --- | --- |
| 错误诊断 A：不符合证据 | 所选诊断与检查证据不符 | `personal_nurse.diagnosis_corrections.diagnose_gastro` |
| 错误诊断 B：无法解释全部结果 | 所选诊断只能解释部分结果 | `personal_nurse.diagnosis_corrections.diagnose_observe` |

- 两个值均为单条非空白字符串，不是台词数组；不得缺句、填空串、纯空格或 `null`。`diagnosis_corrections` 不接受额外键。
- `diagnose_gastro`／`diagnose_observe` 是现有动作的技术ID，并不限定病种，也不代表打乱后的屏幕第一／第三项；不可翻译或随选项位置改名。
- 英文写入 `data/localization/en.json` 的 `strings`，键分别为 `collections.staff.<id>.personal_nurse.diagnosis_corrections.diagnose_gastro` 和 `collections.staff.<id>.personal_nurse.diagnosis_corrections.diagnose_observe`。角色姓名沿用既有本地化，不在对白字段内另加说话人标签。
- 不要写到 `personal_nurse.dialogue.insufficient_evidence` 等旧提示数组中；这两句有独立的诊断错误出口。实装需验证两种错误动作、正确动作继续、中英文、说话人归属及重绘／读档。
- 非专属护士、医生及药剂师不强制提供此映射；成美 `doc_aoi` 保留共用病例原有的两句，不复制到护士字段。若任何角色主动配置该映射，仍须完整提供A/B两句。
- 运行时缺句回退仅为兼容防线，不代表新角色可以缺少必需对白；不能为了通过校验擅自关闭已获用户确认的专属护士资格。

已实装的七名护士原文依据见 `tools/fixtures/nurse_diagnosis_corrections_zh.json`；该文件用于回归核对，不是给新角色套用的通用台词模板。

### 地点闲谈必需数据

- `profile.json` 的 `presence.fixed_locations` 或 `presence.random_locations` 包含 `lounge` 时，须提供至少3段休息室独立回应。天台是独立规则，`presence.rooftop_enabled` 默认true，因此即使普通地点列表不含 `rooftop`，也须提供至少3段天台回应；只有显式false才免除且不得注册天台闲谈。当前只有千鹤禁用天台。两处都允许则至少6段。不得为通过校验擅自改变出场资格或补写原文。
- 地点ID须存在于地点表。普通随机池排除固定岗重复项与天台；固定岗为空代表80%分支不出现。安琪／弘子“所有地点”指公共工作地点，不包括私人办公室。地图分配不限制专属护士看诊或手术团队。
- 角色目录中保存 `time_events.json` 数组，并在本人的 `bundle.json` 注册 `"time_events": "time_events.json"`；只创建文件不注册不算完成。每个条目的 `actor_id` 必须是该包的角色ID，`location_id` 使用实际地点技术ID；不得借用其他人物台词或放在别人的角色包中。
- 必需字段：`id`、`location_id`、`label`、`actor_id`、`responses`、`minutes`、`repeatable`。每段为一个完整的非空白字符串，不拆成连续的上／中／下篇；同一入口不得重复相同回应，允许超过3段。其他工作地点保持既有数量要求，单入口至少1段，不强制全体医护在每个工作地点都有闲谈。
- 人物闲谈统一 `minutes: 30`、`repeatable: true`，`effects` 不填或为空对象；不设置熟悉度、关系、属性或旗标奖励。微事件、关系事件及无人物的独自活动不是本规则的替代入口。
- 必须体现该人物口吻与场合，适用于普通已相识同事，不无条件预设恋爱进展、刚结束的手术或特定日期。原文或明确创作授权缺失时报告缺口，不自动补写／套用通用占位句。篇幅建议约40–120汉字、1–3句，不是schema长度上限；较长定稿由既有分页展示。
- 中文逐字保留；英文至少覆盖 `collections.time_events.<event_id>.label` 和全部 `collections.time_events.<event_id>.responses.<index>`，按原数组顺序对应。姓名使用医护既有英文名，技术ID、资源路径、触发字段不翻译。
- `content.schema.json` 的 `time_event` 定义校验单条格式、数量、去重及数值；`validate_data.py` 联合检查角色包注册、归属和休息室／天台地点覆盖。本地化检查负责英文完整性，不能因为中文schema通过就宣布交付完成。
- 运行时仍须已相识且人物在场才提供入口；同一段内若包含主角回应，应在原文中明确归属，因为闲谈不会自动切换独立说话人节点。重绘不重抽回应，新一次闲谈从第一页显示。

已导入的51段原文见 `docs/source/HOSHIMI_IDLE_CHAT_51_CHINESE_DRAFT_2026-10-13.md`；写作场合及既有范例见 `docs/idle_chat_writing_handoff_2026-10-13.md`（后者为导入前的历史交接稿，不代表当前缺口）。

### 数值与翻译的处理

- 人物能力定位由用户提供。手术、诊断、协作、患者照护、器械操作、冷静度六项 0–100 数值可由 Codex 拟定，经用户确认后实装。
- 熟悉度初值、增长曲线、关系门槛、冷却、出场阈值若无具体数值，由 Codex 根据用户设定提出方案，不能静默定案。
- 英文翻译、技术 ID、路径和 JSON 由 Codex 处理；指定译名及称呼优先遵循用户要求。

### 统一技术规格

- 普通立绘沿用当前 1024×1536 RGBA PNG、真实透明背景；角色脸型、画风、比例、头部位置和显示锚点保持一致。实际验收以游戏内显示为准。
- 术中 HUD 头像推荐 1200×900 透明 PNG，从手术帽到胸口的紧凑头肩构图。详细标准见 [术中头像清单](intraoperative_staff_avatar_checklist.md)。
- 岗位／剧情 CG 的构图和尺寸按对应显示位置另定，不能照搬立绘规格。
- 原始种子图、生成提示词、原始输出、定稿及 SHA-256 留档；旧素材非经明确授权不覆盖。

## 4. 当前实现限制：接入前由 Codex 核对

这些是现有代码行为，不是替用户决定人物设定的依据；遇到冲突时报告并协商调整。

1. **同行池**：当前按“已认识＋冷却”筛选，没有独立的禁止同行开关。用户要求已认识但不同行时，需要补充明确的筛选支持。
2. **熟悉度与等级**：关系等级锁定不会阻止熟悉度增长。两者必须分别确认。
3. **护士岗位 CG**：验证器对新增女性护士要求三类 CG，即使本批只开放部分岗位；不能把旧角色豁免名单用于绕过新角色要求。如制作范围不符，应先处理规则冲突。
4. **约会档案**：当前新女性医生约会档案检查未排除关系锁定角色。用户不开放约会时，应明确处理检查规则，不能虚构约会内容。
5. **关系槽位**：每人需配置 Lv1–Lv5 五个槽位，可标记 planned 或 unavailable；未开放槽位不是剧情缺失的自动创作许可。
6. **术中头像**：所有角色须登记头像元数据，可标 needed；标 ready 必须有对应透明文件。涉及实际术中显示时应完成素材与验收。
7. **特殊职业**：当前 profession 支持 doctor/nurse/pharmacist，team_category 支持 doctor/nurse。超出已有分类的身份需明确映射或扩展结构，不能擅改人物职业。
