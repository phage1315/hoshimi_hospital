# 日常微事件包 v1

第一批微事件收录七瀬恋与朝倉美幸各10个，共20个事件、60个选择。它们使用 `data/events/micro_events.json` 的独立数据结构，已接入看诊结束、手术结算与地点访问调度器。

每个事件只有一个选择点，但不再是“提问—选择—单句回应”后立刻结束。标准节奏为三句固定铺垫、一次玩家选择、角色的分支回应，再以两句共同收束结束。界面逐句推进，并把选择前、选择后的当前句位置写入存档；关系变化仍只在选择时结算一次。

60个选择中，42个不直接改变关系数值：14个是纯风味选择，28个只留下可供未来对白引用的记忆。其余18个是轻微关系变化，单项变化不超过2点。微事件不会进入CG鉴赏，也不会阻挡主要人物事件。

## 人物语言原则

七瀬恋“细致、温柔坚定”。她的问题常从患者动作、团队节奏与照顾习惯开始，不直接逼问私人感情。她会接受玩家的疲惫与坦白，但涉及患者和交接时保持职业立场。

朝倉美幸“开朗、认真好学”。她习惯拿小本子提问，也会用食物、口诀和想象旅行缓解专业压力。关系加深后，她逐渐允许谈话离开教学关系，但仍保留年轻护士的好奇与谨慎。

## 调度规则

- `after_encounter`：完成一次接诊后，在离开诊室前抽取；同一患者只抽一次。
- `after_surgery`：手术结果结算后抽取；参与团队中有该角色才有资格。
- `location_visit`：进入休息室、天台、护士站或空闲诊室时抽取。
- 必须满足角色关系、时段、地点和冷却天数；主线、工作事件和主要人物事件优先。
- 每次最多出现一个微事件。满足条件的候选按权重稳定抽取，结果立即写入存档；重绘和读档不重新抽取。
- 同一角色同一天最多触发一个微事件，全院每天建议最多两个，避免日常对白挤占医疗流程。
- 选择的 `memory_tag` 永久保存，未来微事件可用它替换一句回应，也可在约会和冲突事件中形成回声。
- `flavor` 不改变数值；`memory` 主要保存记忆；`soft` 允许很小的关系变化。界面不显示类型。

## 下一步运行时接口

调度器需要接收 `context`、`location_id`、当前时钟、当日触发记录、团队成员、关系数值和近期病例标签。选择完成后保存事件ID、选择ID、触发日和记忆标签，并把非空 `effects` 交给现有关系系统。人物事件测试页不列出微事件；另设开发过滤器即可快速检查全部内容。
