# 人物事件自然触发设计

## 目标

正式游玩时，玩家通过医院日常遇见事件，而不是从章节列表点选。现有「人物事件」页保留为开发测试入口，用于快速检查分支、立绘、条件与存档。

## 事件条件

每个事件使用同一组可组合条件：

- **日期**：最早／最晚工作日，或指定日期。
- **时段**：开始与结束时间；采用医院时钟，不以现实时间判断。
- **地点**：事件只能在定义地点出现。
- **人物在场**：角色排班允许，且没有被另一项工作占用。
- **关系**：隐藏好感、熟悉度、关系等级与事件旗标的最小／最大条件。
- **历史**：要求完成的事件、禁止已完成的事件、选择旗标。
- **上下文**：病例、手术、值班或冲突结果等游戏状态。

触发条件只决定“候选资格”。事件另有 category、priority、cooldown_days、repeatable 与 grace_days，供调度器处理多个同时满足的候选。

## 调度顺序

同一地点、同一时刻最多提供一个主要人物事件，优先级如下：

1. 必须发生的工作／主线事件。
2. 已开始事件的延续。
3. 达到关系阶段的里程碑事件。
4. 与当前病例、手术或近期选择有关的情境事件。
5. 普通日常和随机闲聊。

同级事件先比较显式 priority，再比较已经等待的天数，最后用稳定 ID 决定顺序。事件一旦被选为本次地点访问的候选，就把结果写入存档；退出页面、重绘或读档不重新抽取。

## 时间窗口与错过保护

普通关系事件采用“软时段”。例如午休事件适合 11:30–14:00；当天错过后，下一工作日仍可再次进入候选池。只有明确写为 scheduled_once 的剧情事件才会真正过期。

grace_days 防止高优先级事件一直压住其他内容。候选等待越久，调度权重越高。长手术跨过时段时，不惩罚玩家；事件延至下一个合适工作日。

## 玩家看到的形式

- 医院导览可以显示人物当前大致所在地点，但不展示数值门槛。
- 进入地点后，用情境句作为入口，例如“神宮寺成美的茶已经凉了”“七瀬恋还在核对交接单”。
- 玩家可以进入事件，也可以暂时离开；普通关系事件不会强制打断操作。
- 必须发生的工作事件可以自动进入，但应在发生前给出清楚的场景过渡。
- 已锁章节、精确好感要求和事件 ID 只在「事件测试」页显示。

## 参考模式

- Ren'Py 的条件菜单与屏幕敏感状态证明“显示、禁用、执行”可以由同一份游戏状态决定；本项目不在 UI 回调里复制条件。
- ink 使用全局变量、阅读次数、条件选择和 once-only 选择记录叙事状态；本项目继续用稳定事件 ID、选择 ID 与完成历史重放存档。
- 《To Heart》将事件区分为日期、好感、相遇次数和角色冲突等类型，并把人物与地点选择结合；本项目采用相似的候选分类，但保留医院排班和工作事件语义。
- storylet 方法把短篇内容视为带前置条件、优先级和时间间隔的单元，适合没有强制主线的医院日常结构。
