## 目标

### 普通偶遇与剧情事件的边界（2026-10-14）

- 普通地图每人每小时80%固定岗位、20%随机地点，各分支只选一处；无固定岗位时80%不出现。随机池排除固定岗位及天台。休息室属于普通随机地点，取消额外非午间概率；12:00（含）至13:00（不含）若无人，从允许去休息室的合格人物中调入一人，不复制普通位置，不限最多两人。
- 候选先经过已相识、既有周日值班筛选。天台独立按半小时50%出现一名，不占普通位置；默认所有合格医护可去，仅 `presence.rooftop_enabled: false` 排除，当前只有千鹤。专属护士看诊、手术团队另按原规则，不绑定地图位置。
- 日期／人物／小时固定普通分配；天台单独按日期／半小时抽样，候选按技术ID排序。世界状态相同则往返、读档、中英切换相同；推进时间到新时段后再进入刷新，进入本身不耗时。
- 此机制不是专属事件调度器：`show_location()` 仍先处理进行中事件、地点特殊事件与人物事件，再绘制普通偶遇；不得用普通概率阻止符合前置的剧情。
- 沿用现有地点闲聊文本、30分钟等既有耗时和人物资料入口，不自动给缺少闲聊文本的角色补写对白。
- FEATURE-031已按用户定稿补齐十名角色的17个入口／51段回应（包括明日香天台）；仅增加对应人物在场时的闲谈，不绕过人物相识／地点在场门槛，不增加熟悉度效果。每次开始新闲谈重置展示页码，重绘保持当次随机回应。
- FEATURE-038追加8名角色的10个入口／30段及完整英文，覆盖新增休息室／天台资格。安琪、弘子保留固定岗并扩展公共工作地点随机池；千鹤无固定岗，随机手术室／护士站／休息室。多于四人的普通地点使用可滚动人员抽屉。
- 地点型微事件（`context: location_visit`，界面“日常片段”）必须由当前 `staff_present_at(location_id)` 中的角色触发；按钮可见性与点击选取共用同一资格检查，不因“已相识”就召出未在场角色。进行中的片段保持原会话，不中途重抽。门诊结束／术后微事件保留各自原有上下文规则，术后仍要求参与该台手术。普通闲谈与微事件是独立内容：没有该地点闲谈台词的在场角色仍只提供资料入口，不能借用其他角色台词填补。

正式游玩时，玩家通过医院日常遇见事件，而不是从章节列表点选。现有「人物事件」页保留为开发测试入口，用于快速检查分支、立绘、条件与存档。

## 事件条件

每个事件使用同一组可组合条件：

- **日期**：最早／最晚工作日，或指定日期。
- **时段**：开始与结束时间；采用医院时钟，不以现实时间判断。
- **地点**：事件只能在定义地点出现。
- **人物在场**：角色排班允许，且没有被另一项工作占用。
- **关系**：隐藏好感、熟悉度、关系等级与事件旗标的最小／最大条件。
- **历史**：要求完成的事件、禁止已完成的事件、选择旗标。
- **上下文**：病例、手术、值班或冲突结果等游戏状态。

触发条件只决定“候选资格”。事件另有 category、priority、cooldown_days、repeatable 与 grace_days，供调度器处理多个同时满足的候选。

## 调度顺序

同一地点、同一时刻最多提供一个主要人物事件，优先级如下：

1. 必须发生的工作／主线事件。
2. 已开始事件的延续。
3. 达到关系阶段的里程碑事件。
4. 与当前病例、手术或近期选择有关的情境事件。
5. 普通日常和随机闲聊。

同级事件先比较显式 priority，再比较已经等待的天数，最后用稳定 ID 决定顺序。事件一旦被选为本次地点访问的候选，就把结果写入存档；退出页面、重绘或读档不重新抽取。

## 时间窗口与错过保护

普通关系事件采用“软时段”。例如午休事件适合 11:30–14:00；当天错过后，下一工作日仍可再次进入候选池。只有明确写为 scheduled_once 的剧情事件才会真正过期。

grace_days 防止高优先级事件一直压住其他内容。候选等待越久，调度权重越高。长手术跨过时段时，不惩罚玩家；事件延至下一个合适工作日。

## 玩家看到的形式

- 医院导览可以显示人物当前大致所在地点，但不展示数值门槛。
- 进入地点后，用情境句作为入口，例如“神宮寺成美的茶已经凉了”“七瀬恋还在核对交接单”。
- 玩家可以进入事件，也可以暂时离开；普通关系事件不会强制打断操作。
- 必须发生的工作事件可以自动进入，但应在发生前给出清楚的场景过渡。
- 已锁章节、精确好感要求和事件 ID 只在「事件测试」页显示。

## 参考模式

- Ren'Py 的条件菜单与屏幕敏感状态证明“显示、禁用、执行”可以由同一份游戏状态决定；本项目不在 UI 回调里复制条件。
- ink 使用全局变量、阅读次数、条件选择和 once-only 选择记录叙事状态；本项目将世界状态直接写入 state dictionary。事件鉴赏可以独立回放，但玩家存档不依赖剧情日志回放。
- 《To Heart》将事件区分为日期、好感、相遇次数和角色冲突等类型，并把人物与地点选择结合；本项目采用相似的候选分类，但保留医院排班和工作事件语义。
- storylet 方法把短篇内容视为带前置条件、优先级和时间间隔的单元，适合没有强制主线的医院日常结构。
