# M1 / 首位患者的门诊体验

## 如何玩

F5 → 开始游戏（或直接医院导览）→ 门诊诊室 → 音羽響子。

1. 接诊：直接问诊或先安抚患者。
2. 问诊：一次「基础问诊」整理疼痛变化、伴随症状、既往史与过敏，完整内容进病历。
3. 查体：一次「基础查体」整理体征和腹部检查结果。
4. 检查：选择血液检查与腹部影像；也可以加做没有新线索的检查，额外花费 15 分钟。
5. 判断：依据右侧病历选初步诊断。不符合线索时有同事反馈，记录一次修正机会的使用，可重新选择。
6. 沟通：向患者解释安排后才能收住院。
7. 交接：完成页显示用时、判断修正次数；病房显示已收住院的患者。

不能重复计时或重复收住院。完成的选项会收起；未解锁的下一步显示「待补齐线索」。检查没有现实计时器，选择后立即出结果，游戏内时间按定义推进。

## 存读档

门诊底部有「保存」「读档」，导览底部也可存读档。只有一个手动槽位，再次保存会覆盖它。载入有未保存进度时提示确认；新游戏也会在有病例进度时提示确认。没有存档时标题页的继续游戏按钮不可用。损坏、不兼容或逻辑无效的存档会显示错误，保留内存进度。

保存内容：已经进行的病例选择、收集到的记录、时间、当前阶段、最近的反馈与住院状态。恢复时回到当前病例。入职对话位置、界面位置、滚动位置不保存；没有自动存档。

实际存档位于 Godot 的 `user://clinic_slot_1.json`，通常是 macOS 的 `~/Library/Application Support/Godot/app_userdata/星见医院 · 春日序章/clinic_slot_1.json`，以 Godot 的用户数据目录设置为准。

## 体验边界

这是虚构病例的线索与叙事体验，结果和决策路径有意简化。没有提供医疗处置技术，也未实现手术、用药、患者急剧恶化或关系奖励。暂不对玩家做综合医疗能力评分；完成页的用时和判断修正次数只反馈游戏选择。

## 0.4 / 阅读节奏调整

- 大幅缩短阶段提示、对白与选项。单次对白以一两句为主，结果提示仅保留一个信息点。
- 人物图扩大至 450×389 的等比显示区域，底部为独立对话框；移除长期占据右侧的病历栏。
- 右下角「病历 · N 条新记录」按需展开；进入诊断阶段自动展开，离开该阶段收起。诊断时仍可手动关闭。
- 基础问诊的三项、基础查体的两项各合并为一次操作，不增加额外「继续」点击。接诊时直接问诊 / 安抚的选择，以及检查、诊断、沟通选择保留。
- 详细信息仍完整记入病历，收起不丢失线索。检查等待时间保留为选项旁的简短提示。
- 旧行动 ID、耗时及前置条件不变，合并按钮只执行尚未完成的子行动，保持 0.3 版存档兼容，包括只做完一部分问诊的存档。
- 119 项门诊断言通过，新增折叠 / 展开、自动展开、新记录数、合并操作防重复和旧存档续接检查。图形布局仍需本机游玩确认。
